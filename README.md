# Бот записи клиентов + мини-CRM

Telegram-бот для онлайн-записи (салоны, барбершопы, мастера, репетиторы, автосервисы) и веб-админка
для владельца. Один раз собранное ядро, которое под каждого клиента меняется настройками и списком услуг.

## Что умеет

**Бот** — услуга → мастер → дата → время → подтверждение. Если подходящий мастер один, шаг выбора
пропускается. «Мои записи» с отменой, напоминание перед визитом, уведомления администраторам.
Занятое время скрывается, двойная запись невозможна, ближайшее время ограничено (`MIN_LEAD_MIN`).

- **Услуги по мастерам.** У каждого мастера отмечаются услуги, которые он выполняет. Клиент видит
  только подходящих мастеров. Если у мастера не отмечено ничего, он выполняет все услуги.
- **Телефон клиента.** После первой записи бот просит номер кнопкой «Поделиться номером»
  (можно пропустить, позже — командой `/phone`). Принимается только собственный контакт клиента.
  Номер виден в админке и в уведомлениях администратору.
- **Предоплата** (по желанию). Время удерживается за клиентом, бот выставляет счёт через Telegram Payments,
  после оплаты запись подтверждается. Не оплатил за `PAYMENT_HOLD_MIN` минут — бронь снимается,
  время снова свободно.

**Админка** (`/`) — ближайшие записи с отменой (видны телефон и статус оплаты), клиенты, услуги
(добавить, скрыть), мастера: рабочие окна по дням недели и список выполняемых услуг.

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env        # затем впишите BOT_TOKEN, ADMIN_PASSWORD, ADMIN_IDS, BUSINESS_NAME
python -m app.seed          # демо-данные: 3 услуги, 2 мастера, Пн–Сб 10:00–19:00 (можно пропустить)

python -m app.bot                                         # бот (long polling)
uvicorn app.web:app --host 127.0.0.1 --port 8000          # админка: http://127.0.0.1:8000
```

Бот и админка — два отдельных процесса с общей базой.

### Как получить токен

В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен в `.env`.
Токен даёт полный контроль над ботом, поэтому:

- держите его только в `.env` (файл в `.gitignore`), не вставляйте в код, чаты и issue;
- если токен где-то засветился — `/revoke` в BotFather выдаст новый, старый перестанет работать.

## Предоплата

1. В [@BotFather](https://t.me/BotFather): `/mybots` → ваш бот → **Payments** → выберите платёжного
   провайдера и пройдите подключение. Список провайдеров зависит от страны и меняется.
   Начните с **тестового** токена провайдера и тестовой карты.
2. В `.env` задайте `PAYMENT_PROVIDER_TOKEN`, `PREPAYMENT_PERCENT` (например, `30`), при необходимости
   `PAYMENT_HOLD_MIN`. Пока не заданы оба значения (токен и процент), предоплата выключена.
3. Перезапустите бота. Клиент увидит сумму предоплаты на экране подтверждения, получит счёт и после оплаты — подтверждение.

Как это работает:

- запись создаётся в статусе «ждёт предоплату» и **занимает время**, но напоминания по ней не идут;
- Telegram перед списанием спрашивает бота, можно ли принять платёж: бот отказывает, если бронь
  истекла, отменена или сумма не совпадает;
- если бронь успела истечь, а клиент всё же оплатил, запись восстанавливается, когда время ещё
  свободно; иначе клиент и администраторы получают сообщение «нужен возврат» с номером платежа;
- **возвраты бот не делает**: при отмене оплаченной записи администратор получает уведомление и
  возвращает деньги вручную в кабинете платёжного провайдера;
- если Telegram не принял счёт (например, сумма ниже минимальной у провайдера), бронь снимается,
  клиент видит сообщение, администраторы — предупреждение.

> Платёжный сценарий покрыт автотестами на подменённом Telegram, но с реальным провайдером он здесь
> не запускался. Перед боевым включением проведите тестовую оплату от начала до конца.

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен бота (обязателен для `python -m app.bot`) |
| `BUSINESS_NAME` | `Мой салон` | название в приветствии и шапке админки |
| `ADMIN_IDS` | пусто | Telegram ID через запятую для уведомлений |
| `ADMIN_USER` / `ADMIN_PASSWORD` | `admin` / пусто | доступ в админку; **пока пароль не задан, админка закрыта** |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс бизнеса, в нём хранятся все времена |
| `DATABASE_URL` | `sqlite:///./booking.db` | строка подключения SQLAlchemy |
| `SLOT_STEP_MIN` | `30` | шаг сетки времени |
| `MIN_LEAD_MIN` | `60` | за сколько минут до начала ещё можно записаться |
| `BOOKING_DAYS_AHEAD` | `14` | горизонт записи в днях |
| `REMINDER_BEFORE_MIN` | `120` | за сколько минут напоминать |
| `PAYMENT_PROVIDER_TOKEN` | пусто | токен платёжного провайдера из BotFather |
| `PREPAYMENT_PERCENT` | `0` | доля стоимости, которую просим заранее (0–100) |
| `PAYMENT_CURRENCY` | `RUB` | валюта счёта |
| `PAYMENT_HOLD_MIN` | `15` | сколько минут держим время до оплаты |

## Структура

```
app/
  config.py      настройки из окружения и .env
  models.py      Service, Master, WorkingHours, Client, Booking (+ связь мастер–услуга)
  db.py          движок, сессии, текущее время бизнеса, автодобавление новых колонок
  booking.py     вся логика записи: слоты, создание, отмена, предоплата, напоминания (без Telegram и веба)
  keyboards.py   inline-клавиатуры; состояние записи кодируется в callback_data
  bot.py         обработчики aiogram, платежи и фоновый цикл (напоминания, снятие неоплаченных броней)
  web.py         админка на FastAPI (HTTP Basic, защита POST от CSRF)
  templates/     шаблоны админки
  seed.py        демо-данные
tests/           83 теста, сеть не нужна
```

## Тесты

```bash
python -m pytest
```

Покрыты расчёт слотов, пересечения и двойная запись, отмена (в том числе чужой записи), напоминания,
услуги по мастерам, телефон (нормализация, чужие контакты), предоплата (удержание времени, проверка
платежа, истечение брони, поздняя оплата, возврат), обновление старой базы, сквозные сценарии бота
на подменённой сессии Telegram, а также доступ, экранирование и CSRF-защита админки.

## Что важно знать перед боевым запуском

- **HTTPS для админки.** HTTP Basic передаёт пароль открытым текстом. Наружу публикуйте только за
  обратным прокси с HTTPS (Caddy, nginx) или держите панель на `127.0.0.1` и ходите через SSH-туннель.
- **Обновление базы.** При запуске бот и админка сами создают недостающие таблицы и **добавляют новые
  колонки** в существующие, так что после обновления кода данные не теряются. Переименования и
  удаление колонок так не делаются — для них подключите Alembic.
- **Один процесс бота.** Защита от двойной записи рассчитана на один работающий экземпляр бота.
  Для нескольких экземпляров нужен PostgreSQL и блокировка/ограничение на уровне базы.
- **Время без часового пояса.** Все времена хранятся «настенными» в `TIMEZONE`; менять пояс уже
  работающего бизнеса нельзя без пересчёта записей.
- **Резервные копии.** Для SQLite это один файл `booking.db`: копируйте его по расписанию.

## Куда развивать

Перенос записи, отзывы после визита и рассылки «давно не были», выручка и аналитика в админке,
отметка «визит состоялся», автоматические возвраты через API провайдера, вебхуки вместо polling,
шаблон под разные ниши.
